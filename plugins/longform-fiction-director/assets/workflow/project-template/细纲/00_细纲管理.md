# 细纲说明

细纲只是作者写给自己看的临时笔记，不是正文施工表，也不是每章必填文件。事情已经想清楚时，可以直接写正文。

需要细纲时，只在 `01_当前章细纲.md` 里用普通话写几段连贯文字：从上一章的真实局面接起，讲清本章事情怎样继续、人物作了什么选择、相关人物怎样回应、局面最后改变在哪里，以及什么仍没有说透。容易写错的史实和人物知情范围写到相关位置即可，不另列清单。

重要章节可以写得更充分，过渡章节可以更短；篇幅只看是否足够支撑动笔，不是验收线。作者要细纲时不要只给几句章概，也不要为凑长度增加事件、人数、天数和比例。

不要制作表格，不分配段落字数，不编号安排固定场景，不规定前几百字必须出现什么，不预先设计读者依次提出的问题，也不要求每章都有反转、兑现或悬念。系统信息、人物反应和世界说明只在正文当下真正需要时出现。

不强制七项字段，不固定场景数，不规定影响后续几章，也不设置“不可调整节点”。细纲开始替人物决定每一步或写成完整对白时，就删回必要因果。正文写完后，只把实际发生的事实更新到台账；没有写进正文的细纲内容仍然只是想法。
