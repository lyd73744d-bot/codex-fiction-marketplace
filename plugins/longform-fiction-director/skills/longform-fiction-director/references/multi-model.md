# 多模型编排（总责编调度）

> Codex 永远在**总责编位**，外部写作模型默认在正文 A 位。模型推荐是责编建议，作者可随时覆盖；详细边界见 `editor-model-division.md`。

## 怎么接入模型

1. 插件首次初始化会打开字字珠玑绑定页；使用账号密码登录或注册。插件不接收模型供应商 API 密钥。
2. MCP 登录后调用 fiction_list_models，从字字珠玑后台实时读取当前真正可用的模型，不在插件里写死线路。
3. 再调 fiction_recommend_models，传入任务类型（draft/outline/humanize/review…）。
4. 推荐模型时说明 `billing` 中的模型费率、预计消耗和余额；作者当次选择使用后才以 authorConfirmed=true 调用 fiction_generate_to_file。带 `chapterNo` 时默认写入正文并覆盖同章；调用前会再次核对余额，长文传 background=true，本地核对连续性后用 fiction_generation_status 取回结果，再读正文文件；返回中要报告调用后的余额和 chargeStatus。

## 任务 → 模型角色

| 任务 | 角色 | 默认倾向 |
|---|---|---|
| 脑洞/市场 | 探索 | deepseek-v4-flash / doubao-seed-2-1-turbo / glm-5.2 |
| 大纲/细纲/章节构思 | Codex 总责编默认本地完成；需要第二意见才调用 | glm-5.2 / claude-sonnet-5 / kimi-k2.6；gemini-3.1-pro-preview 只作作者点名后的候选 |
| 正文 | 主写 | claude-sonnet-5 / deepseek-v4-pro；长篇历史正文优先 claude-opus-4-6。glm-5.2 只作作者点名后的备选并人工复核；minimax-m3 不自动用于长篇正文 |
| 去AI味 | 风格 | claude-sonnet-5 / glm-5.2 / deepseek-v4-pro |
| 质检 | 审核+连续 | claude-sonnet-5 / glm-5.2 / gemini-3.1-pro-preview；硬伤再上 Claude Opus |
| 定稿 | 成稿 | claude-opus-4-6（作者确认前） |

模型推荐只从当前目录中选择。作者点名的保留模型可以手动调用，但不会替代其他模型、也不会因失败自动换线。

## Codex 对作者的说话方式

- 每次先推荐一个模型并展示费率、预计积分和余额，再询问是否使用；当次选择使用才调用
- 默认够用就行，不堆旗舰
- 结果默认直接落 `正文/`；同章重写覆盖，确认采用后才入台账
- 作者拒绝时不抢写，也不新建临时稿；继续把这一章想清楚
- 调用失败：保留已成功结果与错误，不静默重复扣费

## 传输纪律（重要）

长文传输默认：

1. callModels 先走流式请求并持续保存已收到内容
2. 空流也不切换非流式协议重发；网络、限流、5xx、超时或已有部分正文均不重复提交
3. 作者当次确认后，业务层用 fiction_generate_to_file（authorConfirmed=true）把全文写入正文文件
4. 展示/质检都读文件，不靠聊天窗口里的半截流

## 调用纪律

1. 只从 fiction_list_models 返回的清单里选
2. 不在项目文件里存密钥
3. 每个模型只拿完成角色所需的最小上下文
4. 原始结果直接落盘到正文；只有作者明确要求多个版本时才落候选
5. 不以多数票代替判断
6. 未经作者确认采用不得写入事实台账


## 传输策略（单次流式 + 完整落盘）

1. 长文只提交一次流式请求
2. 网络、限流、空流、5xx、超时或部分正文都不自动重发；任何重试或续写都重新征得作者确认
3. 只有成功返回空流时才尝试一次非流式协议兼容
4. 默认写入 正文/第XXX章_标题.txt；临时稿兼容路径只在作者明确要求保留版本时使用
5. txt 可被模型再次读取做质检/去AI味/文风对比
6. 聊天只给路径+短预览

## 可靠性（fusion.14）

- 单次流式优先；超时不重发，只有空流响应才做一次非流式兼容。
- 默认只调用作者明确选择的第一个模型，不自动换模型；只有作者本次明确要求 `fallbackChain=true` 时，才按给定顺序依次尝试。
- 硬门槛拦截：过程泄漏 / 审稿腔包装 / 空输出；通过后才落盘。
- 产物：正文/*.txt；临时稿兼容路径不进入普通写作流程。
- 优化：`fiction_optimize_with_models` 默认只用一个主模型并覆盖同章；作者明确给多个 modelIds 时才按模型顺序串行。
