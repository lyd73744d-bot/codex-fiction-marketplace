# Skill 持续进化

## 三层记忆

1. 任务观察：本次接受、拒绝、手改差异和原因，保存在项目反馈记录中。
2. 项目规则：只对当前书生效，保存在 `.fiction-director/learning/active-skill.md`。
3. 核心 Skill：跨项目稳定有效的方法，随插件版本发布。

单次反馈或一次否定不直接变成永久规则。作者明确说“以后本书都这样”时可以直接成为项目规则；否则至少要有多个独立片段的同类证据，且没有明显反例，才提出候选。

## 进化流程

### 观察

记录原结果、作者操作、接受或拒绝原因、适用题材与场景。只记录事实，不替作者猜动机。

### 候选规则

每条候选必须包含：触发条件、建议动作、禁止动作、保留功能、例外、证据链接或项目片段哈希。公开网络经验只能成为候选，不能直接启用。

### 对照评测

同时选取作者接受过和拒绝过的片段，比较启用前后结果。检查事实保真、人物声音、套路重复、阅读顺滑度、字数变化和是否产生新问题。评测样例不得只选支持候选的内容。

### 批准与版本

Codex 给出评测结论和变更摘要。作者明确批准，或作者授权 Codex 在证据充分时批准后，才生成新版本。记录版本号、启用日期、规则差异、证据和评测结果。

### 回滚

保留上一版本和启用前快照。新规则造成事实丢失、人物同声、文风变冷、模板增多或跨场景误判时，立即回滚并把失败记录加入评测集。

## 提升到核心 Skill 的门槛

项目规则只有在多个项目中重复有效、得到公开方法或编辑经验的独立证据支持，并通过回归场景后，才能作为核心 Skill 候选。核心 Skill 不得在后台静默覆盖；更新必须形成可审阅文件与版本记录。
