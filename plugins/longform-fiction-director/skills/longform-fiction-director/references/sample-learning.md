# 样书学习制度

样书是校准材料，不是第二套正文模板。学习的目标是看懂作者在具体场景里做了什么取舍，以及这种取舍为什么在当时有效；不是把一本书压成若干条万能规则。

## 先观察，不急着归纳

第一次阅读只从剧情、对话和文风各截少量完整片段，保留文件名与行号。剧情看一件事怎样引出下一件事，对话看双方各自想要什么、说了多少，文风一起看措辞、长短句、段落换气、叙述距离和说透程度。剧情与对话优先保留连续几段，文风优先保留一整句或一小段；宁缺勿碎。没有原文位置可核对的判断，不写成结论。

摘句不是金句库。每类只留少量代表片段，长度以能看清小说语境为准；不得整份发送给正文模型。学习的是原作者在当时为什么这样安排，以及产生了什么阅读效果，不直接复制剧情、标志性词组、句式或段落顺序。

`fiction_sample_book` 的 `learn` 只负责从长文本里找到可回看的完整片段。随后由 Codex 直接读这些片段，在“随手记”下面用一两句自然话写出实际看见的东西；不要把统计数字改写成结论，也不要把空栏目留给作者填写。作者想让其他模型参与分析时，先推荐并询问本次是否使用，结果仍只是候选看法。

样书真正的用途很简单：帮当前稿看见另一种可行写法。剧情可以参考因果怎样衔接，对话可以参考人物怎样绕开、试探或停住，文风可以参考句子怎样落地和留白。觉得有用就试，没用就放着；只有作者认可、并且确实适合本书的少量习惯才沉淀进文风锚点。它不替代作者口味，也不生产“万能文风”。

统计句长、段长、对话比例只能帮助寻找值得细读的位置，不能变成正文目标。不得由“短段较多”推出“本书必须多用短段”，也不得把“某章有悬念”写成“每章必须钩子”。

## 结合当前项目筛选

同一种写法离开人物、题材和场景后可能失效。每条观察都要再问：它解决了样书里的什么问题；当前项目有没有同样的问题；如果采用，会不会伤害本书已经成立的声口、视角或节奏。

不适合当前项目的优点也可以承认，但不带入本书。多个样书意见冲突时，以作者当前意图和已确认正文为准，不拼成平均文风。

## 小范围试用

样书观察优先用于审读已经生成的候选，而不是预先命令正文。只把当前场景真正用得上的一两点拿出来，例如“这场谈判不用让双方说透”或“这个结果应该由前面的选择自然带出”；数量不是硬规定，目的是避免把整份分析压给写作模型。

修改后检查是否产生了同样的阅读效果，而不是检查句式是否像样书。不得复制原句、标志性措辞、人物、设定、完整桥段、事件顺序或章法顺序，也不得要求模型“模仿某位作者”。

## 确认后才进入本书 Skill

本地分析和外部模型分析都只是候选观察。作者没有确认前，只留在 `样书/书名/00_手法学习笔记.md`，不得自动写入 `辅助文档/10_本书写作Skill.md`，不得整份发送给正文模型。

确认后的本书 Skill 只保留当前项目会长期用到的少量习惯，用自然话说明，不写固定次数、字数、句长、场景数、开篇方式或章尾形式。每次正文调用只摘录当章确实相关的一两条。
