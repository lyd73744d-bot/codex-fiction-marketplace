# 从四个网文项目拆解出的提示词方法论（已本地化）

只吸收**结构与检查法**，不照搬外仓原文。结合本插件原则：候选先落盘、作者确认才入台账、每次调用其他模型前都重新询问。

## 学到的四条主结构

### 1. 入口轻、协议重（天命）
- SKILL 只负责：识别当前阶段、按需加载有关资料、把眼前这一步做完
- 细则放 references，需要时再读
- 过程对话保持自然；只在整章完成、质检完成或作者问进度时给短状态摘要

本插件映射：
- 入口：`longform-fiction-director/SKILL.md` + 本目录 references 的写作梯子
- 协议：本目录 references
- 里程碑摘要：`delivery-dashboard.md`

### 2. 写前信息应少而准
- 旧版曾采用逐场控制卡，实测会让模型把正文写成验收清单，现已撤销。
- 只有承接或事实容易写错时，才留一页以内自然笔记；不规定开头、节拍、场景数量和收尾。

本插件映射：`chapter-control-card.md` 仅保留兼容文件名，内容已经改为可选章节笔记。

### 3. 网文专项只能按需使用
- 平台兑现和系统规则可以单独观察，但不能变成每章打勾表。
- 只有作者明确追求对应节奏或正在诊断某项问题时才读取。

本插件映射：`hook-shuangdian-checklist.md` 不再默认并入质检。

### 4. 去 AI 味要分级、改味不改剧（Daisy deslop）
- 先扫描再改；轻度/中度/重度不同删改上限
- 只改说法，不改剧情、伏笔、人设

本插件映射：`deslop-grades.md` + `humanizer-zh`

## 本插件坚持不动的差异

1. 默认一步步；连续跑可授权，但不自动入台账
2. 脑洞先由 Codex 问清，收束前可建议一次外部发散；细纲、正文、去AI味和质检如需模型同样逐次询问
3. 网关可永久绑定，但每次模型调用仍需作者当次确认
4. 绑定辅助文档重读，不靠模型记设定
