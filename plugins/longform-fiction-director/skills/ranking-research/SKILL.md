# 公开榜单研究

用插件 MCP 做事实采集，Codex 只负责解释。扫榜本身不调用模型，也不需要网关登录。

## 怎么做

1. 平台、榜名或分类不清楚时，先用 `fiction_rank_sources` 读取当前可用项，不猜 ID。
2. 用 `fiction_scan_rankings` 抓取一次公开榜单。项目目录已知时默认 `save: true`，把 Markdown 和 JSON 放进 `辅助文档/市场与榜单/`；纯临时查看可不保存。
3. 用户问“最近涨了什么”时，用 `fiction_compare_rank_snapshots` 比较至少两次快照。只有一份快照时，只说当次可见分布，不说趋势。
4. 番茄结果若带字体映射或私用区字符警告，不分析受影响的书名、作者和简介；改用内置浏览器核验公开页面，或明确说明这一部分暂时不可确认。

## 解释边界

- 观察和判断分开说。榜位、标题、作者、分类、简介、字数和页面可见数值是观察；“读者可能在期待什么”是责编判断。
- 一次榜单不能证明题材正在爆发，两次快照也只证明这两次之间发生了位次变化。
- 只研究标题承诺、公开简介、标签组合、字数区间、更新状态和榜位变化。不要复制正文、独特桥段、人物组合或完整剧情。
- 不把榜上作品拆成新书模板，不要求作者照抄高频词。研究的用途是看清读者正在被什么承诺吸引，以及作者自己的脑洞可以怎样做出区别。
- 默认看 10 至 20 本已经够用；用户明确要求更大范围时最多取工具允许的数量，不循环刷站。

## 给作者怎么说

先用几句话说清当次最明显的事实，再给一两个会真正改变创作选择的判断，并说明采用后会放弃或削弱什么。不要交付一张“照着填就会火”的表，也不要承诺成绩。需要继续验证时，指出下一次应在什么时间重扫同一榜单，而不是把猜测包装成结论。
