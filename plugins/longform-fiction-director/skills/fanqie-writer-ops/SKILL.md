# 番茄作家后台操作

默认用 **Codex 内置浏览器 / 电脑控制** 走半自动流程。
不要默认改用 Playwright 批量脚本，除非用户明确要求批量脚本。

## 何时使用

- 上传 / 发布章节到番茄
- 核对线上最新章、字数、审核状态
- 读取书评、书圈、段评、章末讨论
- 根据评论给改稿优先级

## 硬规则

1. **先本地后线上**：本地正文未校验通过，不上传。
2. **先确认目标书和目标章号**，避免发错书/重章/跳号。
3. **是否使用AI 必须选「否」**。
4. **未获用户明确确认时，只做到草稿或停在发布确认前**；用户说「发布/上传/发出去」才点最终确认。
5. **已发布章节默认不改**，除非用户明确要求改已发章。
6. 注意日额度：优先发「今天该更的新章」，旧章替换另说。
7. 操作后必须回列表核验，不只看提交成功弹窗。

## 启动前检查

1. 打开/确认番茄作家后台已登录。
2. 进入目标书的章节管理。
3. 记录：
   - 线上最新章号/标题
   - 今日已发章数或字数（若可见）
   - 本地待发文件路径、标题、纯汉字数
4. 向用户确认一句：
   - 要发哪几章
   - 立即发布还是只存草稿
   - 是否允许点最终「确认发布」

## A. 上传/发布流程（推荐）

可靠路径：

```text
章节管理
→ 选对分卷
→ 新建章节
→ 填章号/标题/正文
→ 保存，确认字数不是 0
→ 下一步
→ 错别字提示：提交
→ 风险检测：确定（仅在用户允许发布时）
→ 发布设置：是否使用AI = 否
→ 立即发布 或 定时发布
→ 确认发布
→ 回章节管理核验：审核中 / 已发布
```

### 填内容要点

- 标题用本地正式章名，不要临时瞎起。
- 正文从本地权威文件粘贴/输入，去掉作者注、校验备注、内部标记。
- 保存后看编辑器字数；若为 0 或明显不对，重贴后再继续。
- 多章连发时：**一章走完并核验成功，再开下一章**。

### 失败处理

- 登录失效：停下让用户登录，不反复盲点。
- 页面改版找不到按钮：先截图/读 DOM，再继续；不要乱点。
- 字数异常、重章、跳号：停止发布，先本地或列表核对。
- 定时发布距开时不足约 30 分钟：不要再改该定时章。

## B. 读取评论 / 书评流程

入口优先：

```text
作家后台
→ 评论管理 / 书评 / 书圈 / 段评 / 章末讨论
```

最少读这四类：

1. **书评**：整体口碑、劝退点、长评
2. **书圈**：读者讨论主题
3. **段评（近章）**：最近更新段的即时反馈
4. **章末讨论（最新 10 章）**：追更读者当场反应

### 输出格式（直接回对话）

```markdown
## 评论快照
- 范围：书评 / 书圈 / 近章段评 / 最新N章章末
- 线上最新章：第X章《标题》
- 总量观感：...

## 真有用的意见（按优先级）
1. [类型] 原话摘要 —— 影响：劝退/节奏/人设/逻辑
2. ...

## 可执行改稿
- 立刻改：...
- 后续改：...
- 先不改：...（说明为什么）
```

原则：
- 只提炼**可执行**意见，不堆情绪复读。
- 区分：个别人骂 vs 多人同点。
- 近期段评优先服务「下一章怎么写」；书评优先服务「中长期避雷」。

## C. 日更标准动作

用户说「今天上传/日更」时，默认顺序：

1. 对一下线上最新章 vs 本地待发章
2. 校验本地待发章（字数、禁词/项目硬规则若存在、标题）
3. 上传目标章（默认今日额度内）
4. 回列表核验
5. 读近章评论，给下一章注意点

## 与写作插件配合

- 正文生产、去 AI 味、质检：走写作技能 / longform 主流程。
- 本 skill 只负责 **作家后台上传 + 评论读取 + 线上核验**。
- 若项目有 `AGENTS.md` / 写作引擎，以上传前本地规则为准。

## 不要做的事

- 不默认批量脚本硬推
- 不在未确认时点最终发布
- 不把评论原样灌进正文
- 不因为单条极端差评整章推翻，除非多人同点或硬伤坐实
